# 🎓 Smart Campus Resource Utilization & Dropout Risk Analytics Platform

> **Enterprise AI · Analytics · Decision Intelligence**

A production-ready, end-to-end data analytics and machine learning platform that transforms raw student interaction data into decision-ready insights — enabling educational institutions to proactively prevent dropout and optimise campus resource utilisation.

---

## 📌 Business Problem

Educational institutions are sitting on vast amounts of student interaction data — LMS logins, attendance records, library visits, assignment scores — yet decisions about at-risk students remain reactive and intuition-driven. This platform changes that by providing:

- **Predictive Dropout Risk** per student with explainable ML
- **Deep EDA** revealing hidden patterns in engagement and resource utilisation
- **Actionable Recommendations** for administrators, not just data scientists

## 📊 EDA Highlights

| Notebook | Key Finding |
|----------|-------------|
| 01 — Overview | 10,000 synthetic students, 9 raw features, 8.95% observed dropout rate |
| 02 — Data Quality | 2–5% missing values in behavioural features; IQR outliers in LMS logins |
| 03 — Univariate | Attendance is left-skewed; assignment scores show bimodal distribution |
| 04 — Bivariate | Dropout students have median attendance 20pp lower; 3× more disciplinary actions |
| 05 — Multivariate | PCA: first 3 components explain 81.5% variance; clear dropout cluster separation |
| 06 — Business | Top KPI for admin: `engagement_index < 40` → immediate intervention trigger |

## 🤖 ML Model Comparison

| Model | ROC-AUC | F1 | Precision | Recall |
|-------|---------|----|-----------|--------|
| Logistic Regression | 0.848 | 0.362 | 0.235 | 0.793 |
| Random Forest | 0.844 | 0.440 | 0.523 | 0.380 |
| Gradient Boosting | 0.844 | 0.380 | 0.620 | 0.274 |

> Values copied from `models/metrics.json` (produced by `src/models/train.py`) on a held-out split of the **synthetic** dataset. Dropout is rare (8.95%), so precision/recall trade off sharply and the three models are essentially tied on AUC. Because the data is generated from a hand-written logistic model, these numbers say nothing about real-world performance.

> **Data note:** all data is synthetic, generated by `src/ingestion/generate_data.py`. No real student records are used.

## 🚀 Quick Start

### Prerequisites
```bash
python 3.10+ | pip
```

### 1. Install dependencies
```bash
cd smart-campus-analytics
pip install -r requirements.txt
```

### 2. Generate data & train models
```bash
python src/ingestion/generate_data.py
python src/preprocessing/clean.py
python src/features/engineer.py
python src/models/train.py
```

### 3. Run the Streamlit dashboard
```bash
streamlit run dashboard/app.py
# → http://localhost:8501
```

### 4. Run the FastAPI backend
```bash
uvicorn src.api.main:app --reload --port 8000
# → http://localhost:8000/docs
```

## ☁️ Streamlit Cloud Deployment

1. Push this repository to GitHub
2. Visit [share.streamlit.io](https://share.streamlit.io)
3. Connect repository → set **Main file**: `smart-campus-analytics/dashboard/app.py`
4. Set **Python version**: `3.11`
5. Add `requirements.txt` from the project root
6. Click **Deploy** ✅

> **Note:** Pre-generate data and models locally, then commit `data/processed/` and `models/` to the repo before deploying (add exceptions to `.gitignore`).

## 🎯 Intended Use

This is a portfolio project on synthetic data. It has not been deployed or evaluated with real institutions, so no measured business impact (dropout reduction, advisor time saved, efficiency gains) is claimed. The risk score and KPIs (e.g. `engagement_index < 40`) are meant as inputs to advisor triage, not validated interventions.

---

## ⚖️ Ethical Considerations

- **Fairness**: Model must be audited for demographic bias before production use
- **Transparency**: All predictions are explainable via feature importance
- **Privacy**: No PII stored; student IDs are anonymised
- **Human-in-the-loop**: AI is decision support, not automated gatekeeping
- **Consent**: Students should be informed before their data is used for scoring
